## 3. แก้ Code.gs ในโครงการ Public เดิมเพียงสองจุด
**จุด A: ใน `getPublicData()` หลังบรรทัด `const all=allState_();` เพิ่ม**
```js
const inventory=boriwanInventory_(all);
```
**ใน return object ของฟังก์ชันนั้น** เปลี่ยน
```js
catalog:all.catalog.filter(x=>x.enabled),summary,
```
เป็น
```js
catalog:inventory.filter(x=>x.enabled),inventoryEnabled:true,summary,
```

**จุด B: ใน `submitDonationWithSlip(form)` ที่ถือ `LockService.getScriptLock()` แล้ว**
หลังบรรทัด
```js
const items=validateItems_(form.items);
```
เพิ่ม
```js
boriwanValidateStock_(items,all);
```
ตรวจให้แน่ใจว่าตัวแปร `all` มาจาก `const all=allState_();` ใน lock เดียวกัน
เพื่อป้องกันคนสองคนกดส่งชิ้นสุดท้ายพร้อมกัน

## 4. บันทึกและ Deploy Apps Script
Deploy > Manage deployments > Edit (รูปดินสอ) > Version: New version > Deploy
คง URL `/exec` เดิมไว้ ตรวจว่าหน้า Public ยังส่งสลิปได้และ Admin รับรายการจริง
**ไม่ต้องแก้ URL GitHub, Worker, Turnstile หรือ Script Properties**

## 5. ทดสอบก่อนใช้รับเงินจริง
1. เปิดลิงก์ GitHub เดิม กด Ctrl+F5
2. ผ้าไตรรอง ต้องเห็นเหลือ 2/2, สังฆทานเหลือ 10/10
3. เครื่องขันหมากต้องเห็น "เต็มแล้ว" (มีผู้จองล่วงหน้า)
4. พยายามเลือกผ้าไตรรองเกิน 2: ปุ่มและช่องต้องจำกัดไม่ให้เกิน
5. ส่งสลิปทดสอบหนึ่งรายการ, จากนั้นรีเฟรช: ชิ้นที่ส่งต้องลดทันทีแม้ Admin ยังไม่อนุมัติ
6. คนอีกคนเปิดพร้อมกันและส่งเกินจำนวน: ฝั่งเซิร์ฟเวอร์ต้องปฏิเสธอย่างปลอดภัย
7. หลัง Admin อนุมัติ จำนวนที่กันไว้ต้องยังคงถูกหัก ไม่ถูกหักซ้ำ
8. หลัง Admin ยกเลิกรายการทดสอบ จำนวนต้องคืน; ตรวจใน Dashboard และ Catalog อีกครั้ง

## ความหมายของสถานะ
- กำลังเลือกสินค้าในหน้าเว็บ **ไม่กันของ** (เพราะระบบนี้ส่งรายการพร้อมสลิป ไม่มีขั้นจองแยก)
- ส่งรายการพร้อมสลิปสำเร็จ **กันจำนวนทันที** ทั้งสถานะรอตรวจ/ยอดมีปัญหา/อนุมัติแล้ว
- ผู้ดูแลยกเลิกรายการจึงคืนจำนวน (ถ้ารายการนั้นไม่ถูกยืนยัน/ยกเลิกอย่างขัดแย้ง)
- เปิดหน้าเว็บก่อน Deploy ข้อ 4 จะเห็นเพียง "จำนวนจากเอกสาร" ไม่ใช่จำนวนที่จองไว้ทั้งหมดแบบเรียลไทม์
- นี่เป็นขีดจำกัดของระบบ **ป้องกัน oversell ตอนส่งสลิป** ไม่ใช่ระบบล็อกก่อนโอนเงิน 20 นาที
- ห้ามนำโค้ด InventoryStock.gs ไปใส่โครงการ Admin หรือเว็บบริจาคเงินกฐินเดิม
